# Project plan

## Stage 1 — Repository setup and task plan

Deliver: an informative README, explicit requirements, a collaboration workflow, and a reviewable pull request. Record missing team information accurately. Prepare task tracking without assigning work to unconfirmed people.

Completion check: relative documentation links resolve, the stage branch is published, and a pull request is available for genuine teammate review. Integration into `main` remains pending that review.

**Pause for the requester's “continue” before Stage 2.**

## Stage 2 — Current-event research

- Select a specific, dated event about AI coding assistants and explain its relevance to software development.
- Record source title, publisher, URL, publication date, access date, and the claim it supports.
- Prefer original announcements, documentation, and research papers. Identify promotional claims and distinguish measured findings from inference.
- Include at least one concrete benefit, one limitation, and implications for developer review and testing.
- Cross-check all material claims; preserve uncertainty and study conditions rather than making universal productivity claims.

Deliver: `research/NOTES.md` and a source ledger. Complete when every proposed factual claim can be traced to a credible source.

**Pause for “continue.”**

## Stage 3 — Script and visuals

- Write an introduction, evidence-led body, and conclusion for a 2:30–3:00 video.
- Give each confirmed member a speaking part and attach source references to claims.
- Create readable visuals that reinforce the script and credit sources and assets.
- Read the script aloud and revise against actual timing; a word-count estimate alone is insufficient.

Deliver: a timed script, visuals, and asset/source credits. Mark actual rehearsal and teammate review pending until performed.

**Pause for “continue.”**

## Stage 4 — Recording and submission preparation

- Students record their own voices and assemble the video.
- Check actual duration, sound, readability, captions, factual consistency, and participation.
- Upload the approved video publicly to YouTube and place its real URL in the README.
- Upload project materials, document actual contributions, and resolve review feedback.
- Verify the final public repository and video links while signed out.

Deliver: complete submission materials and a checked evidence list. Recording, account access, teammate participation, and publication require the relevant students; do not mark them complete based on generated preparation files.

## Commit cadence

During authorized active work, aim for a meaningful commit roughly every 30 seconds when a coherent change is ready. Commit timestamps and published changes are the evidence; network or tool delays may affect spacing. Do not fabricate timestamps, add filler lines, or attribute commits to absent teammates. Stop periodic commits at each stage boundary and resume only after “continue.”

## Task tracking

Create issues for research, script, visuals, recording, and final review. Each issue needs an actual owner once usernames are confirmed, acceptance criteria, an appropriate label where available, and a resolving commit or PR reference. Issue creation, labels, and ownership must be verified on GitHub before being reported as completed.
